Running Agents and Tools in an AgentVM Box

An agent that can run commands can do anything your account can. An AgentVM box is a separate macOS, running in a virtual machine on this Mac, that an agent or a model's tools can work in. What they do there stays there, apart from the one project folder you share with it.

What you need

  • macOS 27 or later. On an older macOS, Cadabra works as before and everything runs on this Mac.
  • The AgentVM app. It is a separate application. It installs the agent-vm tools, downloads macOS for the virtual machines, and makes the images and boxes. Cadabra makes none of these itself. Get the app from github.com/abra-code/AgentVMApp/releases.

Where Cadabra needs AgentVM and it is not set up, a Set Up AgentVM... or Open AgentVM button opens the app, or its download page when the app is not on this Mac.

Images and boxes

WordWhat it is
ImageA prepared macOS with programs installed (developer tools, agents). It is a template and never runs your work.
Kept boxA copy of an image that you make in the AgentVM app and that stays until you delete it. What is installed or logged in there is still there next time.
New disposable boxA copy of an image that Cadabra makes for one chat window and deletes when the window closes. Nothing done inside it is left, except the changes in the project folder.

macOS runs at most two macOS virtual machines at a time, so at most two boxes run at once. A box also uses the memory it was given for as long as it runs.

Choosing where things run

An external agent (Claude Code, Codex, and others)

In the ACP Agents window, the Runs in menu offers this Mac, each kept box, and a new disposable box from each image. In a box, the agent and every tool it starts run inside the box.

A local model

The model itself always runs on this Mac: it needs the Mac's memory and graphics processor, and it only produces text. Its tools are what act. In Agentic Session Tools, Where tools run offers this Mac, each kept box, and a new disposable box from each image. With a box chosen, the pane Tools in the AgentVM Box sets which tools run there:

  • Files and shell - files and commands, anywhere in the box.
  • Apply sandbox inside the VM box - also limits Files and shell to the project and the box's temporary folders. Off by default: the box is the boundary.
  • PDF and Allow PDF editing.
  • Date & Time.
  • Internet - search & fetch - off by default. A new disposable box then allows any public host.
  • Read-only project - the tools can read the project and change nothing in it.

What the box can see

  • The project folder, at the same path as on this Mac, shared live: a change made in the box is a change on this Mac at once. It can be shared read-only.
  • Nothing else of this Mac. Not your home folder, your other projects, your Keychain, your browser or your mail.
  • The network the box allows. A box has its own list of hosts it may reach. Everything else is refused and recorded.

If the project is in a folder macOS protects, such as Desktop, Documents or Downloads, programs in the box may be refused it. Cadabra says so in the chat window, with the fix: give the box's image Full Disk Access in the AgentVM app.

The box line in a chat window

A chat window that uses a box shows a line under the model button: the box, how the project is shared, how many hosts were reached and how many were refused, and how many files changed. Hold the pointer over it for the host names.

  • Network... lists the hosts the box reached and those it was refused. Allow in This Box... allows a refused host now; the agent's next try gets through. Allow for This Agent... also allows it in every new disposable box made for that agent.
  • Changes... opens Review Changes (below).

Keys and logins

An agent in a box cannot read the keys on this Mac, so it has to be given one. Keys... in the ACP Agents window stores an API key or token in your login Keychain and gives it to the agent in its box.

Programs in the box can read the key they are given, and can send it to any host the box may reach. Prefer a key you can revoke.

An agent that logs in through a browser, with no key to store, needs a kept box: a login made in a disposable box is deleted with it. Open a Shell in the AgentVM Box in the Agent Keys window opens Terminal in the kept box to log in there once.

Asking before acting

In a box, an agent works without asking by default. That is the point of the box: it keeps the agent away from the rest of this Mac, and a snapshot lets you undo what it did to the project. The level can be changed in the ACP Agents window for agents that support it.

Review and undo

Before a session starts, Cadabra takes a snapshot of the project (Snapshot the project first in Agentic Session Tools; on by default for a box, off for this Mac). Afterwards, Changes... on the chat window's line, or Review Changes on a conversation in the history, shows what changed:

  • Changes that could run something on this Mac later are flagged and listed first: a git hook, an install script, a link that leads out of the project.
  • Undo This Change... puts one entry back as it was. Undo All... puts everything back.
  • Keep Changes... deletes the snapshot. After that nothing can be undone.

When a window closes with flagged changes, Cadabra offers the review before the snapshot goes.

What a box does not protect

  • The project itself. The agent can change or delete anything in it. That is what the snapshot is for.
  • Secrets inside the project, such as a .env file. The box can read them and send them to any host it may reach.
  • The key you gave the agent.
  • What comes back. A file the agent leaves in the project can run on this Mac later, when you build, install or commit. Look at the flagged changes before you do.
  • Anything sent to an allowed host. Allow only the hosts the work needs.

Tools > AgentVM Boxes

A small window listing the boxes and what each is doing. The play button starts the selected box (it stops when Cadabra quits), the stop button shuts it down, and View shows its screen. Open AgentVM opens the AgentVM app, where boxes and images are made, changed and deleted.

A kept box keeps running when its chat windows close, holding one of the two virtual machine slots, unless you stop it. Closing the last window that uses it asks.
