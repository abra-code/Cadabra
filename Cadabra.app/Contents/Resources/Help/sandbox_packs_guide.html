Sandbox Packs

When a model's tools run on this Mac, they run in a sandbox: they can use the project folder and little else. A sandbox pack is a named set of folders for one kind of work, such as building with Xcode or installing packages with npm. You tick the pack instead of adding each folder a tool turns out to need.

What the tools can use without any pack

  • The project folder, to read and change. It is the Project Workspace of Agentic Session Tools.
  • The temporary folders, to read and change, unless you removed them from the tables.
  • The system's own programs and libraries (/bin, /usr/bin, /sbin, /usr/sbin, /usr/lib, /System/Library), to read and run.
  • The folders in the two tables of Agentic Session Tools: a few common tool folders to start with, and the ones you add.

Anything else is refused. A build tool that reads its own files from another folder then fails, often with a message that does not mention the sandbox at all.

Choosing packs

  1. Open Agentic Session Tools (it opens when you load a model with tools, and from the Tools menu).
  2. Under Additional Local Sandbox Paths, click Choose Packs...
  3. Tick the packs you want. Select a pack to see on the right what it holds on this Mac: the folders to read, the folders to read and change, single files, and what it leaves out here.
  4. Click Use These Packs. Nothing changes before that, and Cancel keeps things as they were.

The two tables then list everything the sandbox is given, each folder with where it comes from: You for a folder you added, This session for the temporary folder, or the name of a pack. A pack's folders cannot be removed one by one; untick the pack instead.

Packs apply to the conversations you start after choosing them, on this Mac. A window that is already open keeps what it started with, unless you choose the packs from that window (below). Tools that run in an AgentVM box do not use packs: the box is their boundary.

Choosing packs during a conversation

A chat window whose tools run on this Mac has an Allow Packs... button beside Allow a Folder.... It opens the same list. Use These Packs there does two things: the tools of that window run with the chosen packs from your next message, with the conversation and the model kept, and the same packs are used by every conversation you start later.

Packs are one setting for the whole application, so unticking a pack there takes it from new conversations too. Other chat windows that are open are not changed.

Packs that come with other packs

A pack can use others: CMake builds needs a compiler, so the Make pack comes with it. You tick one pack, and the tables show the folders of the others as "Make and C or C++ builds (with CMake builds)". A pack that comes along but is not installed is simply left out.

What no pack can hold

A pack that names one of these is refused as a whole, whoever wrote it:

  • the home folder itself, its Library as a whole, or the whole disk;
  • folders of keys and logins, such as ~/.ssh, ~/.aws, ~/.gnupg and the Keychains;
  • Mail, Messages, calendars, contacts and the data of web browsers;
  • Cadabra's own data.

You can still add such a folder to the tables yourself with the + buttons. Cadabra asks first, and says what the folder is.

Recording a pack of your own

When no pack fits, let Cadabra find out what a command needs. In the Choose Packs sheet, click Record a Pack...

  1. Command. Type the command, for example cmake -S . -B build && cmake --build build. It is run for real, several times, so use one that is safe to repeat.
  2. Run in. The folder to run it in, normally the project.
  3. Start with the packs ticked in Choose Packs. With this on, the recording starts with those packs and finds only what the command needs beyond them. The pack you save then comes with them. Tick the packs in the sheet first, then click Record a Pack...
  4. Record. Cadabra runs the command in a sandbox, allows what it was refused, and runs it again, until it succeeds. The line beside the buttons says how far it is. Stop ends it.
  5. Review. The table lists what was found. Untick what the pack should not hold, and click an access to switch a folder between Read and Read and change.
  6. Save Pack. Give the pack a title. It is saved, ticked, and listed with the other packs from then on.

What the notes in the review table mean

RowMeaning
Ticked, no noteThe command was refused this folder and ran once it was allowed.
Unticked, WideThe folder holds the data of many programs. Keep it only if nothing narrower works.
Unticked, Contains the folder the command ran inThe folder above the project, with every project beside it. Most commands only look at it and work without it.
UnverifiedThe folder may have been refused to another program that ran at the same time. Check that it belongs to your command.
Unticked, A guessThe command still fails, and this folder was only tried because the command named it or its tools are beside it.
Locked (a dash in the box)The command touched it, but no pack can hold it: one of the folders above, a single file to change, or a folder of which only the listing was needed.

A whole application, such as /Applications/CMake.app, is one row: a tool reads many parts of the application it is in.

When a recording does not succeed

  • The tool starts a sandbox of its own. macOS does not allow one sandbox inside another. swift build needs --disable-sandbox, and xcodebuild needs OTHER_SWIFT_FLAGS='$(inherited) -disable-sandbox' for code that uses Swift macros.
  • The tool needs something that is not a folder: a system service, a simulator, a signing certificate. No pack can give that.
  • The tool does not say what it lacks. Some tools check for a folder without trying to open it, and Cadabra then has nothing to go on. Record on top of the pack for that tool: for cmake with the Xcode generator, tick Xcode and Swift builds first.

The folders found before the command stopped are still shown, and can be saved if they are useful.

Where your own packs are

Each pack you save is one file in ~/Library/Application Support/Cadabra/SandboxPacks, named after its id. To remove a pack, untick it and delete its file. A pack of your own with the id of one that comes with Cadabra takes its place until you delete yours; Cadabra asks before you save one.

Allowing one folder

  • For every conversation: the + buttons under the two tables of Agentic Session Tools.
  • For one conversation that is already running: Allow a Folder... in the chat window. Cadabra also offers it when a tool was refused a folder.
